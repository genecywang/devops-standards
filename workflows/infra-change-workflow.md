# Infrastructure Change Workflow

## Classification

Before implementation, classify:

- Environment: `local`, `CI`, `staging`, `production`, or `shared`.
- Target: `Terraform`, `Helm`, `Kubernetes`, `Jenkins`, `ArgoCD`, `AWS IAM`, `Observability`, `CI/CD`, or `Platform`.
- Risk: security, blast radius, rollback complexity, cost, availability.

## Terraform

Required for Terraform changes:

- `terraform fmt -check -recursive`
- `terraform validate` where initialized and applicable
- `terraform plan` when credentials and backend context are intentionally available

Approval required:

- `terraform apply`
- `terraform destroy`
- `terraform import`
- `terraform state mv`
- `terraform state rm`

## Kubernetes

Required for manifest changes:

- Render manifests if generated by Helm or another template engine.
- Validate schema with `kubeconform` or `kubectl --dry-run=client`.
- Check namespace, RBAC, resources, probes, PDB, HPA / KEDA, NetworkPolicy.

Approval required:

- `kubectl apply`
- `kubectl delete`
- `kubectl edit`
- `kubectl patch`
- `kubectl rollout`

## Helm

Required for Helm chart changes:

- `helm lint`
- `helm template`
- Optional schema validation against rendered output.

Approval required:

- `helm install`
- `helm upgrade`
- `helm uninstall`
- `helm rollback`

## Jenkins / CI/CD

Review:

- Secret handling.
- Credential scope.
- Branch and environment gates.
- Timeout, retry, and rollback stage.
- Artifact retention and audit trail.

## AWS IAM

Review:

- Wildcard actions and resources.
- Trust principals and OIDC subjects.
- Conditions and resource boundaries.
- Privilege escalation paths.
- Rollback path and propagation time.

## Observability

For changes that can fail after deploy, define:

- Metrics.
- Logs.
- Alerts.
- Dashboard or query.
- Runbook or rollback note.
